# Launch kit — Yue 1.2.0

Prepared on 2026-10-08. This is a public preview, not a claim of production-wide compatibility.

## Positioning

For people who read Markdown notes, technical documents and downloaded guides: a calm, lightweight reader with local highlights, without a workspace or editing workflow to configure.

Evidence-backed claims: four muted themes, seven interface languages, shared web/Windows features, local highlights, default-app registration on Windows, an offline single-file HTML edition, and MIT source. The installer excludes the WebView2 Runtime; do not describe its download size as total disk or memory usage.

## English launch draft

Title: Yue — a quiet Markdown reader with local highlights, for Windows and the web

I built Yue for the moment when you just want to read a Markdown file. Open or drop a document, highlight a sentence, and return to the same place later.

The first public preview includes four muted themes, seven interface languages, local highlights, a Windows default-app option, a browser reader and a standalone offline HTML file. The source is MIT licensed.

Documents are processed locally. The web and Windows editions share features but do not sync their data. The Windows installer is unsigned and requires WebView2. Feedback on startup, document opening, readability and translations would be especially useful.

Try it: https://yue-markdown-shiha.txqy0831.chatgpt.site/
Source: https://github.com/shihaitian/yue-reader

## Suggested sequence, not a scheduled campaign

1. Verify the public website, downloads, checksums and GitHub release from a signed-out browser. Test a real Windows installation and .md association on a spare profile or machine.
2. Invite a small group of Markdown readers to test common documents, high-DPI screens and their preferred language. Collect reproducible issues before broad promotion.
3. Adapt the draft for one relevant developer or reading-tools community. Review its current submission rules, disclose that you made the app, include a working demo, and ask for specific feedback. Do not mass-post the same message or manufacture engagement.
4. Publish a follow-up focused on actual fixes and verified feedback. Consider wider launches after installer signing and compatibility checks have progressed.

## Measure without adding tracking

Use GitHub's aggregate release-download counts, repository traffic available to the owner, and labeled issue counts. Record the date and source of each observation. Do not report clicks, active users or retention that have not actually been measured. The reader currently includes no behavioral analytics.

Suggested feedback categories: startup/file opening, annotations/data, readability/themes, language, and platform compatibility. Keep documents private; ask for a synthetic reproduction where possible.
